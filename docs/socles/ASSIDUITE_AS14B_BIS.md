## 1. Ce qui est fait
**Réutilisé tel quel :** la file du matin AS6 (`/assiduite/file-du-matin`, `niveau_de`) et les actions déjà offertes (je prends, traiter, prévenir maintenant, vigilance, relancer l'appel, faire l'appel à la place, confirmer l'arrivée, tracer un contact).

**Ajouté (ce qui manquait) :**
- **Exclus du jour** (`GET /assiduite/exclus-du-jour`) : la file AS6 ne montre un exclu qu'après 10 minutes (alerte « non arrivé »). Le panneau liste tous les exclus dont l'arrivée n'est pas confirmée, marqués « Dans le bandeau Urgent » à partir de 10 minutes.
- **Heure de bascule** (`ent_asd_tableau_reglage`, 2254, `GET /assiduite/tableau/configuration`, `PUT …/heure-bascule`) : 11 h par défaut, 6 h à 18 h, heure locale de l'établissement, réglable par la direction (`assiduite.regle_gerer`). Table dédiée plutôt que `ent_asd_regle`, qui est datée et figée par un mois arrêté (R-AS15) : une préférence d'affichage ne doit ni créer une version de règle ni être gelée.
- **Disposition personnelle** (`ent_asd_tableau_pref`, 2255, `PUT/DELETE …/preference`) : rang, replié, masqué par panneau ; aucune ligne = automatique ; mémorisée côté serveur par utilisateur (retrouvée sur un autre poste). Les cinq panneaux, une fois chacun, sont exigés par le serveur.
- **Regroupement par panneau** : fait dans le frontend (fonction pure `regrouper`), car le DTO de la file suffit : urgent = `urgence`, `non_arrivee`, `apres_presence` ; absents = `sans_nouvelles` (vigilance d'abord, mineurs avant majeurs, le plus ancien d'abord) ; familles = `non_jointe` ; appels = `appel_non_fait` ; incohérences = `incoherence`. Une catégorie inconnue n'est rangée nulle part et est comptée (message).

**Écran** (`composants_metier/tableau_vs/`, monté sur l'accueil des profils qui ont `appel.verifier`) : bandeau Urgent toujours visible (ni rang, ni repli, ni masquage ; « Rien d'urgent » discret quand il est vide) ; avant l'heure de bascule : absents en premier et en grand ; après : exclus et appels non faits en premier et en grand ; « Disposition » (monter, descendre, masquer, « Revenir à automatique », heure de bascule pour la direction) ; actualisation toutes les minutes qui saute son tour quand le focus est dans le tableau ; téléphone : colonne unique, Urgent en tête, chaque panneau repliable.

## 2. Écarts, limites, choix à valider (à ne pas masquer)
1. **Replier en mode automatique est local à la page** (n'épingle pas l'ordre, sinon l'ordre ne suivrait plus l'heure) ; en mode choisi, il est mémorisé. L'écran le dit.
2. **Panneau « Exclus » et bandeau** : un exclu de plus de 10 minutes apparaît dans les deux (marqué). À arbitrer si le pilote préfère un seul endroit.
3. **Mode choisi : aucun panneau « grand »** (l'ordre est celui de la personne).
4. **Heure simulée** : `?heure=HH:MM` dans l'adresse ne joue que sur la disposition (essais, formation, parcours) ; aucune donnée ni droit.
5. Les incohérences n'ont pas d'appel identifié dans la file : l'action est un lien « Ouvrir la journée ». Pas de traitement en ligne d'une incohérence (AS6 §3.6 : lues à la volée, sans trace).
6. Le panneau « Absents » regroupe les `sans_nouvelles` seulement ; une famille tentée sans succès est dans « Familles à rappeler » (non_jointe), pas en double.
7. **Lecteur d'écran** : non testé avec un vrai lecteur (axe-core ne suffit pas, `FRONTEND_LEPTOS.md` §6).
8. Les droits d'affichage des boutons viennent de `/roles/mes-droits` ; un rôle libre sans `absences.lire` voit une erreur d'accès plutôt qu'un tableau.
9. Pour le parcours navigateur, les alertes « non arrivé » sont posées par SQL dans la base **locale** de test : la tâche système qui les crée tourne dans le binaire `ent-api`, pas dans `ent-web-server`. Aucune base de production n'a été touchée.

Le code serveur de la tuile est inchangé.
